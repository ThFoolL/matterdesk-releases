# MatterDesk 安装

有数把飞书里的讨论整理成桌面待办。帮助用户安装并打开窗口，再引导说明关注范围、连接飞书。首次设置后默认随 Codex 自动启动，不需要每次输入启动口令。

## 向用户说明安装过程

公开说明和对话回复面向使用有数的人。用日常语言讲清当前步骤、结果以及用户下一步需要做什么，不讲编译桥接、marketplace 来源、运行环境、内部工具名、字段名或发布检查。不要描述开发者自己的业务、历史对话或开发过程；示例使用通用工作场景。只有用户主动询问技术问题时才解释对应细节。

用户把公开链接和“安装并初始化有数”的要求发给 Agent 时，按安装流程准备插件和桌面程序并打开首次引导；已经装好时复用现有安装。新安装插件尚未加载到当前对话时，使用下方同一份安装脚本继续；确实需要新开对话时说明原因。“设置有数”“打开有数”等只是触发请求的例子，不能要求固定口令或告诉用户每次都要输入。若宿主提供插件设置入口，也可以通过该入口执行本安装技能。

用户要求检查更新时，先通过 `codex plugin marketplace upgrade matterdesk-codex` 更新公开插件，再按更新后的安装流程检查桌面程序；不要把检查旧版 component.json 描述为已检查最新版本。插件工具尚未刷新时，新开对话或使用更新后的公开插件安装脚本。更新保留个人数据，说明实际安装状态。

以下工具、字段和脚本是 Agent 执行步骤，不要求用户自行查路径、管理提示词或安装运行环境。必要的飞书登录和授权仍交给本人完成。

Codex 本机安装完成后，可调用 `matterdesk_launcher` 显示原生「有数悬浮窗」应用页。进入可见的全屏页会自动呼出悬浮窗，不需要第二次点击；对话内预览保留打开按钮。页面预加载不启动窗口，失败可手动重试，不调用模型。侧栏的快捷操作直接呼出窗口；主图标由宿主固定为打开全屏页，不能说成完全不切换内部页。宿主发现此应用后也可在插件详情提供打开应用入口；侧栏是否显示和固定由宿主管理，不承诺自动添加。不要另开浏览器启动页或创建桌面、开始菜单入口。用户只要求打开窗口时直接调用 `matterdesk_window` 的 show，程序已退出时会重新启动。

首次打开窗口先引导填写「主要关注的业务范围」：用户用日常语言说明关注的业务、职责和不需跟进的内容，保存到 classification.businessScope，只在本机生效。可以稍后填写，设置页和设置小助手都能继续修改；升级时未填写的用户会收到一次补充引导，已有个人规则保留。接入飞书前可先完成这一步，不让用户编写提示词，也不预填作者的业务。业务范围影响归类和巡检，不扩大读取权限或采集范围；保存后下一次普通巡检分批应用存量，也可主动重新整理。

1. 当前版支持 Windows 10/11（64 位）和 Codex 桌面应用。公开安装地址是 https://github.com/ThFoolL/matterdesk-releases ，插件名 `matterdesk@matterdesk-codex`。Agent 通过公开仓库安装插件，并从对应下载版本准备桌面程序。不修改用户的 Codex 模型配置，也不在插件缓存运行 npm 安装。
2. 首次安装或插件升级后，组件不匹配时提供两个轻量工具，无需预装 Node.js。先用 `matterdesk_setup_status` 检查；用户要求设置、打开或更新有数时调用 `matterdesk_install_components`，后台安装返回后可继续聊天。用 status 按进度查看，running=true 时不重复安装。失败可重新调用安装工具。安装入口固定读取插件自带 component.json 的版本和校验值，不能改成不明下载地址、跳过哈希验证或切换别人的应用目录。安装完成打开首次引导，Codex／Claude Code 新开会话加载完整工具，DSH 关闭再开启有数插件一次；完整工具已可用时直接用 `matterdesk_window`。此过程保留 GitHub marketplace 来源、用户数据与个人配置，不重新注册成本地插件源。不要把任何密钥作为命令行参数。
   如果宿主暂未暴露轻量工具，可由 Agent 执行插件目录的 `scripts/setup.ps1`（PowerShell RemoteSigned），它执行同一份受校验安装流程；用户不需要自己查路径、装 Node.js 或运行 npm。无法执行本机脚本时再给 https://github.com/ThFoolL/matterdesk-releases/releases 的完整 ZIP 备用入口。确认 installed/ready 的实际状态后再说明安装完成；排队和下载中不等于完成。
3. 模型接口直接继承宿主 Agent 的本机 API 配置，设置页分别选择主力和高速模型并测试连接。主力默认跟随 Agent，思考强度可选低/中/高、默认中；高速从真实列表自动优先选择 DeepSeek v4.1 Flash，缺少时跟随主力，思考保持低。两者复用同一份已有接口与认证。每个宿主首次使用默认继承自己的模型配置；安装其他宿主插件不覆盖已保存的选择。设置中可明确选择 Codex、Claude Code 或 DeepSeek Harness，切换来源时清空旧模型选择、从新来源真实列表选择。选择 DSH 时需要宿主正在运行，模型通过 ctx.llm 调用，不提取或复制其密钥。Claude Code 读取用户级 API 配置或已有环境变量，不执行凭据 helper、不读取项目级配置、不把订阅登录视为 API Key。只报告脱敏状态，不能输出凭据。列表不可用时保留 Agent 当前模型，不让用户手填接口或密钥。
4. 接入飞书时按下方连接助手流程操作，自动检查已有配置，只询问缺少的信息。缺少 lark-cli 时先通过 install_cli 使用飞书官方完整安装向导，安装连接工具及配套 Agent 技能，再继续应用选择和本人授权；无需用户提前手动安装 Node 或 lark-cli，不另做独立安装器。群聊与私聊默认开启，按时间读取本人可见会话，无需用户逐个选择群。首次巡检前可调整历史天数，默认3天；文档按需添加。
5. 机器人消息事件仅覆盖机器人可见且用户选择的群，不等于个人全部消息；轮询始终可用。不要向任何群发测试消息。
6. 默认自动归类并纳入明确事项；不确定的信息附原因留在待确认。待确认页的“自动归类”可再次整理积压，也可用 matterdesk_classify_inbox。用户可关闭自动纳入，改为手动确认建议。无数据、认证失败、未收到事件不能声称同步完成。
7. 首次引导最后一步询问是否立即巡检，并提供默认勾选的自动巡检，默认间隔1小时。用户确认完成设置后才开启；未立即巡检时，第一次自动巡检在本机下一个整点开始，后续从上次巡检完成时间起算间隔。重启续接已保存的计划，不重置计时；反馈处理期间顺延等待。升级保留已有选择。关闭窗口是隐藏，退出程序停止巡检，电脑休眠后恢复补扫。

用户数据在当前用户的应用数据目录 `MatterDesk`；演示资料在独立 `demo` 子目录。升级插件保留数据，禁止把业务资料、个人配置或凭据提交仓库。公司内分享公开仓库链接即可，每人独立授权。宿主的插件更新更新插件文件；更新后运行本设置流程会检查并安装匹配版本的桌面组件，不替用户开启巡检。

首次设置依次为关注业务范围、连接飞书、选择聊天与文档、开始巡检四步，只显示当前步骤；已保存的范围、已添加的聊天与文档不重复铺在后续页面上。中断或重启后继续未完成步骤；可明确选择稍后设置，之后在设置页或通过本助手继续。新安装尚未确认引导时飞书采集与定时巡检关闭；最后一步用户确认自动巡检和是否立即巡检后才执行。升级不覆盖既有设置。只读取用户选择范围内的资料，只在用户选择后发起应用创建或补充权限，不自动扩大采集范围。

## 连接助手

连接飞书使用本机引导，按“连接应用 → 本人授权 → 验证连接”推进。飞书连接统一使用官方 lark-cli，禁止控制鼠标、读取浏览器控件或网页凭据，也不让设置 Agent 操作开发后台。先用 connect/check 检查实际 CLI 配置和 auth status --verify；未绑定时默认配置仅是候选，select_app 在用户确认后复用，list_local_apps 列出本机配置并支持按 profile 精确选择，不修改 CLI 默认配置。本机没有合适配置或凭据损坏时调用 connect_app，运行 config init --new --name 独立配置名 --brand feishu；这是通用官方连接向导，网页支持新建和选择已有应用，并非只能新建。原样在系统默认浏览器打开 CLI 输出的官方链接并显示二维码，用户在官方页选择应用、核对变更并确认，CLI 自动接收保存回传配置后接续本人授权，无需返回插件确认网页选择。create_app/choose_existing_app/read_selected_app/connect_selected_app 是旧入口，均兼容到官方向导，不读取网页。use_app_link 只按用户提供的 App ID 匹配本机配置，不获取网页凭据。官方回传不适用于某个已有应用时，connections_open 提供默认收起的本机 App ID/App Secret 备用表单，不要求应用名。密钥仅通过 stdin 进入 CLI，不进入对话、模型、状态或日志。官方向导需应用管理权限，可能要求核对 CLI 模板权限、机器人或发布配置，用户必须自行核对确认，不能承诺所有应用都适用或全程免审，也不自动提交权限、发布或审批。已绑定应用优先复用，不因旧默认应用失效挡住独立官方连接。应用配置和本人授权分开：保存凭据不等于本人登录，网页后台登录不代表 CLI user 身份。凭据就绪后直接申请最小本人读取权限及 offline_access，授权链接生成后原样在默认浏览器打开；用户完成后 continue，再在线验证本人姓名、openId及实际消息读取。不能因为 auth scopes 元数据清单不全要求先配置后台。应用名取现有 API，不扩权，也不阻断授权。真实授权或读取报错明确指出未开通权限时 configure_app(purpose:permissions)只打开官方权限页并显示必要清单，由本人确认后 continue 验证；不操作网页。configure_app(purpose:name)仅重查现有信息。所有阶段可 cancel，保留已有配置和授权，取消后的晚返回不绑定。停止/失败后 connect 从实际 CLI 状态恢复，已保存回传不重复创建。enabled:false仅表示采集关闭；只有实际本人身份与读取验证通过才说明连接成功，新连接随后确认来源、首次巡检和自动巡检。默认消息需要 search:message、im:message.group_msg:get_as_user、im:message.p2p_msg:get_as_user、im:chat:read，表情仅开启简单沟通自动完成时申请，docx/wiki按文档链接追加；offline_access只用于续期。不申请全域、发送写入、通讯录或管理员 scopes/apply。CLI 缺失时 install_cli 使用官方完整安装流程。

三种路径：

1. 本机已有可用 CLI 连接：先展示应用名称、App ID 和候选状态，由用户确认使用，再验证本人和读取能力。其他本机配置可搜索并按 profile 精确选择。
2. 新建或尚未在本机配置的已有应用：打开官方连接向导，用户在官方页选择新建或已有应用并确认。CLI 接收回传，自动接续本人授权；不要求复制链接或密钥，不读取浏览器。官方页面可能要求更改配置，必须由本人核对确认。
3. 某个已有应用不适用官方回传：允许一次本机密码表单输入 App ID / App Secret，默认收起，不要求应用名，不向 Agent 发送密钥。新建仍优先官方向导。

停止连接在每一步可用。网页选择或保存应用只是配置进度，实际本人姓名和用户 ID 经 CLI 在线验证才是已登录账号；最终还要验证消息读取。新连接不直接开启采集，按引导确认消息范围、可选文档和首次巡检设置。保留原有应用、本人授权、个人范围和其他 CLI 配置。

## 随 Agent 自动启动

「设置 → 桌面窗口 → 随 Agent 应用自动启动」默认勾选，支持 Windows 的 Codex 桌面应用、Claude Code 会话启动和已启用插件的 DSH 启动。首次运行桌面程序后自动登记当前用户的启动检测，已运行时保持窗口状态；同一次 Agent 会话中手动退出不会再次拉起，下次打开 Agent 可重新启动。取消勾选并保存会移除自己的检测登记，不退出当前桌面或更改巡检。演示模式仅保存偏好。可通过设置小助手或 matterdesk_settings_update 修改 desktop.autoStartWithAgent；不改动 Agent 的全局配置与授权。

## 通知与手动录入

先判断内容是否需要本人处理/跟进，消息可见和重要性不是责任证据。明确属于其他人的工作、公告和一般进展进入通知，通知没有子事项或待办；用户可标记已读，也可转为已有或新事项下的待办。责任或必要归属确实不明确才待确认。用 matterdesk_notifications 查看，matterdesk_notification_read 标记阅读状态，matterdesk_save_action 手动新增/编辑/转换；转换填写 notificationId，编辑提供 id 和 originalMatterId，未填写的字段保留。只按用户明确要求操作，保留人工字段与完成状态。

首页右上角「＋」菜单及事项详情都可录入；新增与编辑使用共用表单。重整旧分类会备份后将纯通知的自动条目收进本机历史，不撤除手动或已完成条目。不要宣称所有历史已经重整；巡检按对话分批运行，报告实际剩余进度。

巡检先完整读取选定时间范围内的消息分页，再按会话梳理，不在 8 页、10 段对话或 4 分钟时停止。一个群可以并行讨论多个话题，不能按相邻消息或固定条数拆成事项。正常会话整体交给模型；超长会话先读完全部内容并建立话题索引，最多两个独立摘要并行，已完成片段缓存在本机供中断后续用；必须等全部摘要完成后，再合并跨片段的同一话题、处理细节。用户反馈仍优先，暂停和重启后继续已保存的进度。索引本身不创建待办，不替代关注范围和本人责任判断。

用户明确要求全部重新归类时执行完整重整：先备份，读完选定历史。保留真正不明确的条目；模型输出校验失败会纠正重试一次，仍失败的批次保留待重试并继续其他会话。报告实际重读进度、待确认和错误，不能把尝试过全部信息描述为全部成功归类。

完整重整中断后，在相同分类规则下再次执行会从保存的剩余来源续跑；已完成内容不重新读。规则变化时重新备份整理。连续超时的对话保留待重试，不阻塞其他对话；源内容直接关联的待办不受无关历史候选预算限制。

## 简单沟通自动完成开关

「设置 → 个人偏好 → 自动完成简单沟通待办」新安装默认开启，升级保留已保存的开关，旧版缺失该字段时保持关闭。修改其他设置不改变这个独立开关。启用后巡检可依据本人/指定对象的明确答复及 👍、OK、Get、Yes、Done 表情，完成纯沟通待办，执行工作仍手动处理；整个事项始终由用户手动完成。条目显示完成依据并可撤销，撤销后仅手动完成。表情读取失败、不完整或权限不足时保留待办并报告实际失败，不扩权。

事项、待办、待确认主题和通知在外侧提供「手动处理」「处理意见」两个入口。手动处理直接编辑内容与归属，事项可合并到已有事项；处理意见直接输入自然语言，交给独立模型任务。

「处理意见」队列在本机后台运行，意见与结果仅保存在本机。模型复用已配置的 Agent API 接口；用户无需另填接口或提示词。未完成请求在重启后恢复，升级保留队列和历史。处理反馈优先于巡检和后台整理；反馈涉及规则更新时先保存规则，待反馈全部完成后按最终规则完整整理一次，显示进度和重试入口；弹窗在成功入队后关闭。直接在设置中改规则仍可主动完整重整或由下次巡检应用；不替用户开启巡检或自动完成。

## 同机共享与宿主安装

三个入口连接同一份本机资料目录和正在运行的桌面服务，事项、待办、规则、飞书连接与处理队列共同使用。无需再次绑定飞书。不能另建数据目录、迁移到插件缓存、覆盖已有模型来源或为新宿主复制凭据。新版本组件安装在同一应用目录体系，保留数据。各 Agent 分别保存模型来源、主力/高速型号和思考强度，默认继承自己的模型配置；修改当前入口不覆盖其他 Agent。自动巡检采用最近打开悬浮窗的 Agent 配置，已入队意见沿用提交时的配置。当前不提供跨设备同步。

Claude Code 安装：`claude plugin marketplace add ThFoolL/matterdesk-releases`，然后 `claude plugin install matterdesk@matterdesk-claude --scope user`。首次设置工具与 Codex 相同。SessionStart 钩子只按已保存的自动启动偏好复用或打开窗口，不下载、不改个人设置。同一宿主会话手动退出后不反复拉起。

DSH 需要 0.2.2-rc.1 和 Node.js 24.9 或更新版本。在插件页通过 Git 来源安装本仓库的 `plugin-dsh` 子目录，也可用 `dsh plugin --profile <当前profile> add "git+https://github.com/ThFoolL/matterdesk-releases.git#main&path:/plugin-dsh"`。不要编造或覆盖用户正在用的 profile；先确定当前 profile。使用当前宿主官方插件安装流程，需要其确认时遵循实际提示。第一次组件安装后，在 DSH 插件页关闭再开启有数一次，加载完整工具；之后随宿主启动。多个 DSH 同时运行时，第一个实例负责共享的模型入口，退出后在使用中的 DSH 重开有数插件。
