# MatterDesk 安装

事序把飞书里的讨论整理成桌面待办。帮助用户安装并打开窗口，再引导说明关注范围、连接飞书。首次设置后默认随 Codex 自动启动，不需要每次输入启动口令。

## 向用户说明安装过程

公开说明和对话回复面向使用事序的人。用日常语言讲清当前步骤、结果以及用户下一步需要做什么，不讲编译桥接、marketplace 来源、运行环境、内部工具名、字段名或发布检查。不要描述开发者自己的业务、历史对话或开发过程；示例使用通用工作场景。只有用户主动询问技术问题时才解释对应细节。

用户把公开链接和“安装并初始化事序”的要求发给 Agent 时，按安装流程准备插件和桌面程序并打开首次引导；已经装好时复用现有安装。新安装插件尚未加载到当前对话时，使用下方同一份安装脚本继续；确实需要新开对话时说明原因。“设置事序”“打开事序”等只是触发请求的例子，不能要求固定口令或告诉用户每次都要输入。若宿主提供插件设置入口，也可以通过该入口执行本安装技能。

用户要求检查更新时，先通过 `codex plugin marketplace upgrade matterdesk-codex` 更新公开插件，再按更新后的安装流程检查桌面程序；不要把检查旧版 component.json 描述为已检查最新版本。插件工具尚未刷新时，新开对话或使用更新后的公开插件安装脚本。更新保留个人数据，说明实际安装状态。

以下工具、字段和脚本是 Agent 执行步骤，不要求用户自行查路径、管理提示词或安装运行环境。必要的飞书登录和授权仍交给本人完成。

Codex 本机安装完成后，可调用 `matterdesk_launcher` 显示原生「事序悬浮窗」应用页。进入可见的全屏页会自动呼出悬浮窗，不需要第二次点击；对话内预览保留打开按钮。页面预加载不启动窗口，失败可手动重试，不调用模型。侧栏的快捷操作直接呼出窗口；主图标由宿主固定为打开全屏页，不能说成完全不切换内部页。宿主发现此应用后也可在插件详情提供打开应用入口；侧栏是否显示和固定由宿主管理，不承诺自动添加。不要另开浏览器启动页或创建桌面、开始菜单入口。用户只要求打开窗口时直接调用 `matterdesk_window` 的 show，程序已退出时会重新启动。

首次打开窗口先引导填写「主要关注的业务范围」：用户用日常语言说明关注的业务、职责和不需跟进的内容，保存到 classification.businessScope，只在本机生效。可以稍后填写，设置页和设置小助手都能继续修改；升级时未填写的用户会收到一次补充引导，已有个人规则保留。接入飞书前可先完成这一步，不让用户编写提示词，也不预填作者的业务。业务范围影响归类和巡检，不扩大读取权限或采集范围；保存后下一次普通巡检分批应用存量，也可主动重新整理。

1. 当前版支持 Windows 10/11（64 位）和 Codex 桌面应用。公开安装地址是 https://github.com/ThFoolL/matterdesk-releases ，插件名 `matterdesk@matterdesk-codex`。Agent 通过公开仓库安装插件，并从对应下载版本准备桌面程序。不修改用户的 Codex 模型配置，也不在插件缓存运行 npm 安装。
2. 首次安装或插件升级后，组件不匹配时提供两个轻量工具，无需预装 Node.js。先用 `matterdesk_setup_status` 检查；用户要求设置、打开或更新事序时调用 `matterdesk_install_components`，后台安装返回后可继续聊天。用 status 按进度查看，running=true 时不重复安装。失败可重新调用安装工具。安装入口固定读取插件自带 component.json 的版本和校验值，不能改成不明下载地址、跳过哈希验证或切换别人的应用目录。安装完成打开首次引导，Codex／Claude Code 新开会话加载完整工具，DSH 关闭再开启事序插件一次；完整工具已可用时直接用 `matterdesk_window`。此过程保留 GitHub marketplace 来源、用户数据与个人配置，不重新注册成本地插件源。不要把任何密钥作为命令行参数。
   如果宿主暂未暴露轻量工具，可由 Agent 执行插件目录的 `scripts/setup.ps1`（PowerShell RemoteSigned），它执行同一份受校验安装流程；用户不需要自己查路径、装 Node.js 或运行 npm。无法执行本机脚本时再给 https://github.com/ThFoolL/matterdesk-releases/releases 的完整 ZIP 备用入口。确认 installed/ready 的实际状态后再说明安装完成；排队和下载中不等于完成。
3. 模型接口直接继承宿主 Agent 的本机 API 配置，设置页分别选择主力和高速模型并测试连接。主力默认跟随 Agent，思考强度可选低/中/高、默认中；高速从真实列表自动优先选择 DeepSeek v4.1 Flash，缺少时跟随主力，思考保持低。两者复用同一份已有接口与认证。首次安装默认继承当前宿主；安装其他宿主插件不覆盖本机已保存的模型来源。设置中可明确选择 Codex、Claude Code 或 DeepSeek Harness，切换来源时清空旧模型选择、从新来源真实列表选择。选择 DSH 时需要宿主正在运行，模型通过 ctx.llm 调用，不提取或复制其密钥。Claude Code 读取用户级 API 配置或已有环境变量，不执行凭据 helper、不读取项目级配置、不把订阅登录视为 API Key。只报告脱敏状态，不能输出凭据。列表不可用时保留 Agent 当前模型，不让用户手填接口或密钥。
4. 接入飞书时按下方连接助手流程操作，自动检查已有配置，只询问缺少的信息。缺少 lark-cli 时先通过 install_cli 使用飞书官方完整安装向导，安装连接工具及配套 Agent 技能，再继续应用选择和本人授权；无需用户提前手动安装 Node 或 lark-cli，不另做独立安装器。群聊与私聊默认开启，按时间读取本人可见会话，无需用户逐个选择群。首次巡检前可调整历史天数，默认3天；文档按需添加。
5. 机器人消息事件仅覆盖机器人可见且用户选择的群，不等于个人全部消息；轮询始终可用。不要向任何群发测试消息。
6. 默认自动归类并纳入明确事项；不确定的信息附原因留在待确认。待确认页的“自动归类”可再次整理积压，也可用 matterdesk_classify_inbox。用户可关闭自动纳入，改为手动确认建议。无数据、认证失败、未收到事件不能声称同步完成。
7. 首次引导最后一步询问是否立即巡检，并提供默认勾选的自动巡检，默认间隔1小时。用户确认完成设置后才开启；未立即巡检时，第一次自动巡检在本机下一个整点开始，后续从上次巡检完成时间起算间隔。重启续接已保存的计划，不重置计时；反馈处理期间顺延等待。升级保留已有选择。关闭窗口是隐藏，退出程序停止巡检，电脑休眠后恢复补扫。

用户数据在当前用户的应用数据目录 `MatterDesk`；演示资料在独立 `demo` 子目录。升级插件保留数据，禁止把业务资料、个人配置或凭据提交仓库。公司内分享公开仓库链接即可，每人独立授权。宿主的插件更新更新插件文件；更新后运行本设置流程会检查并安装匹配版本的桌面组件，不替用户开启巡检。

首次设置依次为关注业务范围、连接飞书、选择聊天与文档、开始巡检四步，只显示当前步骤；已保存的范围、已添加的聊天与文档不重复铺在后续页面上。中断或重启后继续未完成步骤；可明确选择稍后设置，之后在设置页或通过本助手继续。新安装尚未确认引导时飞书采集与定时巡检关闭；最后一步用户确认自动巡检和是否立即巡检后才执行。升级不覆盖既有设置。只读取用户选择范围内的资料，只在用户选择后发起应用创建或补充权限，不自动扩大采集范围。

## 连接助手

用户要接入时，用 `matterdesk_connections_action` 的 `request: {action:"connect",source:"feishu"}` 检测并启动引导；只询问状态时用 check。异步结果用 `matterdesk_connections_get` 读取，nextSteps 给出当前步骤、说明、下一步 action 或官方 url。用 `matterdesk_connections_open` 打开同一份本机引导页面，尤其是等待用户授权或输入凭据时。不要自动扩大采集范围。

首次连接先询问用户是否已有适合事序的应用。已有应用的选择流程是：先登录 https://open.feishu.cn/app 的开发者后台，查看本人有权管理的应用并核对名称与用途，再绑定所选应用，最后完成本人 OAuth 授权读取资料。开发者后台登录与应用之上的本人授权是两步，不能要求先在没有应用的情况下 OAuth 登录来列应用，也不能把用户可用应用列表当成开发者的应用列表。没有合适应用则优先推荐为自己新建。

不能因为 lark-cli 已配置其他工具的应用就自动借用。connect/check 返回 choose-app 时，detectedAppId/detectedAppName 仅表示已保存的连接候选；展示实际应用名称，缺少名称时由 Agent 在开发者后台核对，不让用户手填名称，不为读取名称额外申请权限。用户明确选择后执行 select_app（appId 使用 detectedAppId，名称已核实时传真实 appName；暂时未知时使用 App ID 识别并继续）。已绑定应用的缺失名称可由 Agent 通过 confirm_app_name 保存，不重置授权。已经为事序明确绑定的应用、本人授权及升级前的事序连接继续使用，不能要求重建。已有其他合适应用由 Agent 核对后通过 connections_open 的本机安全表单绑定，不在对话中输入密钥。

用户选择新建后执行 create_app；缺 CLI 时 install_cli。Agent 自动发起官方向导，处理配置接收、缺失权限核对、本人授权接续和读取验证，让用户只做必要的确认与本人扫码。新建使用独立命名 profile，保留其他工具的应用、授权和默认配置。创建中断后先 connect 检查已保存结果，避免重复创建。cancel 停止当前引导，不删除已创建的远端应用。

connect 会自动发起缺少的本人授权；添加文档时会检查对应读取权限，授权后继续验证并保存关注链接。原样展示 handoff 的链接和二维码，交还用户，用户明确完成后 continue；不要展示链接后立即轮询授权。授权过期则重新发起。

appMissingScopes / permissionRequest 是当前功能的最小用户权限清单。基础消息需要 search:message、im:message.group_msg:get_as_user、im:message.p2p_msg:get_as_user、im:chat:read；不申请宽泛的消息读写权限。云文档仅在添加链接或用户明确选择时申请 docx:document:readonly；wiki:node:read 只在知识库链接需要时追加。im:message.reactions:read 仅在开启简单沟通自动完成后申请。offline_access 只用于 OAuth 续期，不导入应用 API 权限。不要使用 --domain all、全量 --recommend、写入/发送、通讯录或机器人事件权限；高级实时事件另行按用户选择配置，不是接入前提。

优先采用后台免审权限，或应用开发者本人 user_access_token 的免发布调试路径；用户为自己新建应用适合该路径。两个机制不同，不能把开发者可免发布访问推断为其他用户也免审。官方 CLI 将群/私聊读取、群信息、docx/wiki 读取列为推荐权限，但 search:message 不在默认免审推荐清单；实际是否免审/可开发者调用需核对该应用后台并做读取验证。不能保证全程免审，也不能默认要求先发布或找 IT。遇到必需权限明确需审核且开发者路径不可用，说明哪个权限阻碍哪些能力，不自动申请更多权限、扩大数据范围或替用户提交审批。

宿主有浏览器工具时，Agent 应直接处理可处理的官方页面步骤：打开返回链接，填写通用应用名和说明，导入 permissionRequest 最小清单，逐项核对用户身份、用途和是否免审，然后让用户完成必要确认与本人授权；不要把能代填的步骤变成长篇操作教程。官方新建向导没有自定义 scope 参数，若页面默认勾选超出事序用途的权限，取消非必需项；无法调整时改用开发者后台新建空应用并通过本机表单绑定，不确认宽泛的默认清单。遵循浏览器工具的登录、授权要求，不读取/展示密钥，不自动选择批量全选或全公司可用范围。没有浏览器工具时，展示链接/二维码及本机引导说明具体下一步，不声称已自动配置后台。群聊默认自动按时间采集，不要求用户选择群；文档用 add_document 验证链接。验证成功后按用户连接要求 enable_feishu，保留既有范围。

报告实际读取验证结果，区分“保存凭据”“授权有效”“项目/文档读取通过”和“已开启采集”。连接过程只读远端资料，不发消息或写回工单。多人分发不包含作者或同事的个人凭据；公司统一应用密钥不能随客户端分发，应由管理员按内部方案管理。

首次没有事序连接时，先打开 https://open.feishu.cn/app 引导本人登录飞书开发者后台，再从本人有权管理的应用中核对并选择；调用 confirm_console_login 仅记录用户已完成该引导步骤，不能把它当作消息读取授权成功。不得要求用户手填应用名称。应用名称优先自动读取，缺少元数据权限时由 Agent 在已登录页面核对，并通过 confirm_app_name 保存真实名称；只显示应用ID作为暂时识别，不为读取名称扩大权限。CLI 已保存的连接只是候选，不代表开发者后台全部应用。没有适合应用时调用 create_app，官方向导生成登录/创建页面和二维码，完成后自动接续读取授权。默认开启简单沟通自动完成，当前最小权限因此包括表情读取；用户关闭此功能时不额外申请表情权限。

## 随 Agent 自动启动

「设置 → 桌面窗口 → 随 Agent 应用自动启动」默认勾选，支持 Windows 的 Codex 桌面应用、Claude Code 会话启动和已启用插件的 DSH 启动。首次运行桌面程序后自动登记当前用户的启动检测，已运行时保持窗口状态；同一次 Agent 会话中手动退出不会再次拉起，下次打开 Agent 可重新启动。取消勾选并保存会移除自己的检测登记，不退出当前桌面或更改巡检。演示模式仅保存偏好。可通过设置小助手或 matterdesk_settings_update 修改 desktop.autoStartWithAgent；不改动 Agent 的全局配置与授权。

## 通知与手动录入

先判断内容是否需要本人处理/跟进，消息可见和重要性不是责任证据。明确属于其他人的工作、公告和一般进展进入通知，通知没有子事项或待办；用户可标记已读，也可转为已有或新事项下的待办。责任或必要归属确实不明确才待确认。用 matterdesk_notifications 查看，matterdesk_notification_read 标记阅读状态，matterdesk_save_action 手动新增/编辑/转换；转换填写 notificationId，编辑提供 id 和 originalMatterId，未填写的字段保留。只按用户明确要求操作，保留人工字段与完成状态。

首页右上角「＋」菜单及事项详情都可录入；新增与编辑使用共用表单。重整旧分类会备份后将纯通知的自动条目收进本机历史，不撤除手动或已完成条目。不要宣称所有历史已经重整；巡检按对话分批运行，报告实际剩余进度。

用户明确要求全部重新归类时执行完整重整：先备份，按会话逐段读完选定历史，不受普通巡检的10段预算限制。保留真正不明确的条目；模型输出校验失败会纠正重试一次，仍失败的批次保留待重试并继续其他会话。报告实际重读进度、待确认和错误，不能把尝试过全部信息描述为全部成功归类。

完整重整中断后，在相同分类规则下再次执行会从保存的剩余来源续跑；已完成内容不重新读。规则变化时重新备份整理。连续超时的对话保留待重试，不阻塞其他对话；源内容直接关联的待办不受无关历史候选预算限制。

## 简单沟通自动完成开关

「设置 → 个人偏好 → 自动完成简单沟通待办」新安装默认开启，升级保留已保存的开关，旧版缺失该字段时保持关闭。修改其他设置不改变这个独立开关。启用后巡检可依据本人/指定对象的明确答复及 👍、OK、Get、Yes、Done 表情，完成纯沟通待办，执行工作仍手动处理；整个事项始终由用户手动完成。条目显示完成依据并可撤销，撤销后仅手动完成。表情读取失败、不完整或权限不足时保留待办并报告实际失败，不扩权。

事项、待办、待确认主题和通知在外侧提供「手动处理」「处理意见」两个入口。手动处理直接编辑内容与归属，事项可合并到已有事项；处理意见直接输入自然语言，交给独立模型任务。

「处理意见」队列在本机后台运行，意见与结果仅保存在本机。模型复用已配置的 Agent API 接口；用户无需另填接口或提示词。未完成请求在重启后恢复，升级保留队列和历史。处理反馈优先于巡检和后台整理；反馈涉及规则更新时先保存规则，待反馈全部完成后按最终规则完整整理一次，显示进度和重试入口；弹窗在成功入队后关闭。直接在设置中改规则仍可主动完整重整或由下次巡检应用；不替用户开启巡检或自动完成。

## 同机共享与宿主安装

三个入口连接同一份本机资料目录和正在运行的桌面服务，事项、待办、规则、飞书连接与处理队列共同使用。无需再次绑定飞书。不能另建数据目录、迁移到插件缓存、覆盖已有模型来源或为新宿主复制凭据。新版本组件安装在同一应用目录体系，保留数据；模型来源是共同设置，用户明确切换后才生效。当前不提供跨设备同步。

Claude Code 安装：`claude plugin marketplace add ThFoolL/matterdesk-releases`，然后 `claude plugin install matterdesk@matterdesk-claude --scope user`。首次设置工具与 Codex 相同。SessionStart 钩子只按已保存的自动启动偏好复用或打开窗口，不下载、不改个人设置。同一宿主会话手动退出后不反复拉起。

DSH 需要 0.2.2-rc.1 和 Node.js 24.9 或更新版本。在插件页通过 Git 来源安装本仓库的 `plugin-dsh` 子目录，也可用 `dsh plugin --profile <当前profile> add "git+https://github.com/ThFoolL/matterdesk-releases.git#main&path:/plugin-dsh"`。不要编造或覆盖用户正在用的 profile；先确定当前 profile。使用当前宿主官方插件安装流程，需要其确认时遵循实际提示。第一次组件安装后，在 DSH 插件页关闭再开启事序一次，加载完整工具；之后随宿主启动。多个 DSH 同时运行时，第一个实例负责共享的模型入口，退出后在使用中的 DSH 重开事序插件。
