# MatterDesk 安装

MatterDesk 是本地个人事项应用。插件仅提供对话入口，悬浮程序和定时巡检独立运行。

首次打开窗口先引导填写「主要关注的业务范围」：用户用日常语言说明关注的业务、职责和不需跟进的内容，保存到 classification.businessScope，只在本机生效。可以稍后填写，设置页和设置小助手都能继续修改；升级时未填写的用户会收到一次补充引导，已有个人规则保留。接入飞书前可先完成这一步，不让用户编写提示词，也不预填作者的业务。业务范围影响归类和巡检，不扩大读取权限或采集范围；保存后下一次普通巡检分批应用存量，也可主动重新整理。

1. 当前分发版仅测试 Windows x64 的 Codex 桌面插件。公开仓库 `ThFoolL/matterdesk-releases` 是标准 GitHub marketplace，插件名 `matterdesk@matterdesk-codex`。仓库只提供通用技能、编译桥接与组件安装入口，桌面程序和 Node.js 从同版本 Release 获取。不修改用户的 Codex 模型配置，也不在插件缓存运行 npm 安装。
2. 首次安装或插件升级后，组件不匹配时提供两个轻量工具，无需预装 Node.js。先用 `matterdesk_setup_status` 检查；用户要求设置、打开或更新事序时调用 `matterdesk_install_components`，后台安装返回后可继续聊天。用 status 按进度查看，running=true 时不重复安装。失败可重新调用安装工具。安装入口固定读取插件自带 component.json 的版本和校验值，不能改成不明下载地址、跳过哈希验证或切换别人的应用目录。安装完成打开首次引导，新开 Codex 对话加载完整工具；完整工具已可用时直接用 `matterdesk_window`。此过程保留 GitHub marketplace 来源、用户数据与个人配置，不重新注册成本地插件源。不要把任何密钥作为命令行参数。
   如果宿主暂未暴露轻量工具，可由 Agent 执行插件目录的 `scripts/setup.ps1`（PowerShell RemoteSigned），它执行同一份受校验安装流程；用户不需要自己查路径、装 Node.js 或运行 npm。无法执行本机脚本时再给 https://github.com/ThFoolL/matterdesk-releases/releases 的完整 ZIP 备用入口。确认 installed/ready 的实际状态后再说明安装完成；排队和下载中不等于完成。
3. 模型接口直接继承宿主 Agent 的本机 API 配置，设置页分别选择主力和高速模型并测试连接。主力默认跟随 Agent，思考强度可选低/中/高、默认中；高速从真实列表自动优先选择 DeepSeek v4.1 Flash，缺少时跟随主力，思考保持低。两者复用同一份已有接口与认证。Codex 插件默认继承 Codex。只报告脱敏状态，不能输出凭据。列表不可用时保留 Agent 当前模型，不让用户手填接口或密钥。
4. 接入飞书时按下方连接助手流程操作，自动检查已有配置，只询问缺少的信息。默认仅扫描 @本人消息；私聊、关注群、文档由用户选择。
5. 机器人消息事件仅覆盖机器人可见且用户选择的群，不等于个人全部消息；轮询始终可用。不要向任何群发测试消息。
6. 默认自动归类并纳入明确事项；不确定的信息附原因留在待确认。待确认页的“自动归类”可再次整理积压，也可用 matterdesk_classify_inbox。用户可关闭自动纳入，改为手动确认建议。无数据、认证失败、未收到事件不能声称同步完成。
7. 用户启用定时巡检时保存间隔；关闭窗口是隐藏，退出程序停止巡检。电脑休眠后恢复补扫。

用户数据在当前用户的应用数据目录 `MatterDesk`；演示资料在独立 `demo` 子目录。升级插件保留数据，禁止把业务资料、个人配置或凭据提交仓库。公司内分享公开仓库链接即可，每人独立授权。Codex 的 marketplace upgrade 更新插件文件；更新后运行本设置流程会检查并安装匹配版本的桌面组件，不替用户开启巡检。

首次设置分为关注范围和飞书连接两步，中断或重启后继续未完成步骤；可明确选择稍后设置，之后在设置页或通过本助手继续。新安装的飞书采集与定时巡检默认关闭，应用读取验证通过后用户确认连接，再按需主动巡检或开启定时更新。升级不覆盖既有设置。只读取用户选择范围内的资料，只在用户选择后发起应用创建或补充权限，不自动扩大采集范围或开启巡检。

## 连接助手

用户要接入时，用 `matterdesk_connections_action` 的 `request: {action:"connect",source:"feishu"}` 检测并启动引导；只询问状态时用 check。异步结果用 `matterdesk_connections_get` 读取，nextSteps 给出当前步骤、说明、下一步 action 或官方 url。用 `matterdesk_connections_open` 打开同一份本机引导页面，尤其是等待用户授权或输入凭据时。不要自动扩大采集范围。

飞书优先复用已有应用和本人授权。个人登录依赖应用，访问范围受本人资料权限限制。缺 CLI 时可执行 install_cli；缺应用时引导创建个人应用，用户选择后执行 create_app，由官方向导接收配置并自动接续本人登录，不要求手动复制 App Secret。已有应用可通过安全表单绑定。新应用使用独立命名 profile，保留其他 CLI 应用；创建中断后先 connect 检查已保存配置，避免重复创建。cancel 可停止当前引导，不删除已创建的远端应用。

connect 会自动发起缺少的本人授权；需要单独补文档时用 begin_login（documents/both）。原样展示 handoff 的链接和二维码，交还用户，用户明确完成后执行 continue；不要展示链接后立即轮询授权。授权过期则重新发起。appMissingScopes 表示应用层缺少权限，permissionRequest 提供对应后台地址、所需用户权限和可导入的 JSON。只导入这份最小清单，不使用全域授权。后台标为免审的权限可直接开通；是否需要发布/审核以当前公司的实际规则为准，不能一律要求先找 IT，也不能保证全程免审。

宿主提供浏览器工具时，可打开返回的官方链接，辅助填写应用信息或导入权限清单；遵循浏览器工具的登录、授权及确认要求，最终新增权限前由用户确认。没有浏览器工具时，展示链接/二维码及本机引导即可完成同一流程，不依赖某个专用浏览器插件。群用 search_chats 按名称查找，用户选择后 add_chat；文档用 add_document 验证链接。验证成功后按用户连接要求 enable_feishu，保留既有范围。

报告实际读取验证结果，区分“保存凭据”“授权有效”“项目/文档读取通过”和“已开启采集”。连接过程只读远端资料，不发消息或写回工单。多人分发不包含作者或同事的个人凭据；公司统一应用密钥不能随客户端分发，应由管理员按内部方案管理。

## 随 Agent 自动启动

「设置 → 桌面窗口 → 随 Agent 应用自动启动」默认勾选，目前支持 Windows 的 Codex 桌面应用。首次运行桌面程序后自动登记当前用户的启动检测，已运行时保持窗口状态；同一次 Agent 会话中手动退出不会再次拉起，下次打开 Agent 可重新启动。取消勾选并保存会移除自己的检测登记，不退出当前桌面或更改巡检。演示模式仅保存偏好。可通过设置小助手或 matterdesk_settings_update 修改 desktop.autoStartWithAgent；不改动 Agent 的全局配置与授权。

## 通知与手动录入

先判断内容是否需要本人处理/跟进，消息可见和重要性不是责任证据。明确属于其他人的工作、公告和一般进展进入通知，通知没有子事项或待办；用户可标记已读，也可转为已有或新事项下的待办。责任或必要归属确实不明确才待确认。用 matterdesk_notifications 查看，matterdesk_notification_read 标记阅读状态，matterdesk_save_action 手动新增/编辑/转换；转换填写 notificationId，编辑提供 id 和 originalMatterId，未填写的字段保留。只按用户明确要求操作，保留人工字段与完成状态。

首页右上角「＋」菜单及事项详情都可录入；新增与编辑使用共用表单。重整旧分类会备份后将纯通知的自动条目收进本机历史，不撤除手动或已完成条目。不要宣称所有历史已经重整；巡检按对话分批运行，报告实际剩余进度。

用户明确要求全部重新归类时执行完整重整：先备份，按会话逐段读完选定历史，不受普通巡检的10段预算限制。保留真正不明确的条目；模型输出校验失败会纠正重试一次，仍失败的批次保留待重试并继续其他会话。报告实际重读进度、待确认和错误，不能把尝试过全部信息描述为全部成功归类。

完整重整中断后，在相同分类规则下再次执行会从保存的剩余来源续跑；已完成内容不重新读。规则变化时重新备份整理。连续超时的对话保留待重试，不阻塞其他对话；源内容直接关联的待办不受无关历史候选预算限制。

## 简单沟通自动完成开关

「设置 → 个人偏好 → 自动完成简单沟通待办」默认关闭，升级保留明确偏好。首次安装或开启巡检不替用户勾选；仅用户要求时修改 classification.autoCompleteCommunication。启用后巡检可依据本人/指定对象的明确答复及 👍、OK、Get、Yes、Done 表情，完成纯沟通待办，执行工作仍手动处理；整个事项始终由用户手动完成。条目显示完成依据并可撤销，撤销后仅手动完成。表情读取失败、不完整或权限不足时保留待办并报告实际失败，不扩权。

事项、待办、待确认主题和通知在外侧提供「手动处理」「处理意见」两个入口。手动处理直接编辑内容与归属，事项可合并到已有事项；处理意见直接输入自然语言，交给独立模型任务。

「处理意见」队列在本机后台运行，意见与结果仅保存在本机。模型复用已配置的 Agent API 接口；用户无需另填接口或提示词。未完成请求在重启后恢复，升级保留队列和历史。处理反馈优先于巡检和后台整理；反馈涉及规则更新时先保存规则，待反馈全部完成后按最终规则完整整理一次，显示进度和重试入口；弹窗在成功入队后关闭。直接在设置中改规则仍可主动完整重整或由下次巡检应用；不替用户开启巡检或自动完成。
